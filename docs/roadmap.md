# 今後の改善

[READMEへ戻る](../README.md)

以下は改善候補です。実装済みの機能や提供時期を保証するものではありません。

| 優先事項 | 完了を判断する条件 |
|---|---|
| 保存失敗時の復旧フロー | `edit()` での保存失敗後も編集データを回収でき、失敗種別ごとのテストがある |
| ロールバックの基準 | 連続したコミットと編集で、復元する時点が仕様と一致する |
| ロード条件変更時の保護 | フィルター・モード変更時に未保存データを意図せず失わない |
| 終了・競合時の扱い | 自動保存の方針と、競合時のデータ保持・通知が一貫している |
| 標準APIとの互換性 | ローカル走査の枝刈りや各操作の戻り値の方針が明確で、検証されている |
| 実環境の性能計測 | Box Driveで取得・展開・処理・保存を分けて測定し、再現条件を記録している |
| ZIPメタデータの保持 | コメント・時刻・属性など、保持する項目を定義して検証している |

永続キャッシュは、再展開が実測でボトルネックとなった場合の候補です。導入する場合は内容の有効性確認、容量制御、使用中領域の保護、実パス経由の変更との整合性を先に設計します。

GUI、Box API連携、複数端末の排他制御は現行機能に含まれません。
